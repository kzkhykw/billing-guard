# Billing Guard

[English](README.md)

クラウドやAIを使うアプリの請求急増を、公開前に点検するローカルCLIとCodexスキルです。公開ページの動的処理、キャッシュしない取得、有料AIの呼び出し、課金対象のホスティングを検出します。プロジェクトごとの設定ファイルに予算、実際に利用を止める仕組み、公開経路、実装の根拠を記録します。制御が未設定、または予算通知だけの場合、事前検査は失敗します。

## 使い始める

Python 3.9以上が必要です。追加のPythonパッケージやAPI認証情報は不要です。このリポジトリを取得したディレクトリで実行してください。

```sh
python3 scripts/guard.py scan --repo /path/to/app
cp examples/.billing-guard.json /path/to/app/.billing-guard.json
# 対象アプリの設定ファイルに、実際の停止制御と根拠を記入する
python3 scripts/guard.py preflight --repo /path/to/app
```

設定例は、未確認の制御を安全だと誤認しないよう、意図的に検査に失敗します。書き方は[設定ファイルの説明](references/manifest.md)を参照してください。検査に合格しても、実際の請求上限が有効である証明にはなりません。各サービスの管理画面やAPIで設定を別途確認してください。

`.billing-guard.json` には、少なくとも課金先ごとの月額予算と停止方式、確認日時・確認者・確認先、公開GET経路、有料API経路、検出事項の対策、緊急停止手順を記録します。`evidence` には、制御を実装したソースや設定ファイルの相対パスと、その中にある文字列を指定します。検査を通すための架空の根拠は記入しないでください。

## Codexに導入する

このリポジトリのディレクトリで、次を実行します。

```sh
python3 scripts/install_codex.py --dry-run
python3 scripts/install_codex.py
```

導入スクリプトは、ユーザーの `hooks.json` に `PreToolUse` フックを追加し、このリポジトリをCodexスキルとしてリンクします。既存のフックやエージェント指示は保持します。フックは一般的なCLIデプロイ操作と、課金対象と思われるリポジトリから本番ブランチへのpushを事前検査します。

フックだけで全ての公開経路は捕捉できません。Git連携による自動デプロイ、管理画面、専用ツール、Codex以外からの操作には、CIでの事前検査と、サービス側またはアプリ側の停止機構を用意してください。予算メールは、利用を止める設定が確認できない限り請求上限として扱いません。停止設定にも反映の遅れや超過があり得ます。

## テストと検出結果

```sh
python3 -m unittest discover -s tests -v
```

検出は単純なパターン照合なので、誤検出があり得ます。各項目を確認し、実際の対策と根拠を記録してください。
